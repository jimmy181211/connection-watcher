## 项目背景与意义

在排查异常网络连接时，我们经常需要回答一个简单但很难及时确认的问题：

> 我的电脑是否连接过某个IP地址或端口？如果连接过，是在什么时间、Windows当时将它关联到了哪个进程，还能找到哪些与应用有关的背景信息？

Windows资源监视器可以查看当前网络活动，但需要用户持续打开并观察。短暂连接可能在用户注意到之前就已经消失，也无法自动针对指定目标保存记录或提醒。

SocketSight 让用户通过规则指定自己关心的远程 IP、远程端口或本地端口。程序只观察符合规则的 TCP 连接，并保存出现时间、连接状态、观察时长、Windows 报告的进程以及能够取得的，应用背景信息。

它不是资源监视器的替代品，也不是杀毒软件。它的作用是把“我想关注的连接”变成可重复观察、可回顾的记录，帮助用户或网络安全人员进一步调查。

## 项目概述

SocketSight 是一款在 Windows 本地运行的、基于规则的 TCP 连接观察工具。用户启用监控后，程序按设定的间隔读取 Windows TCP 连接表，并处理符合启用规则的连接。该软件也支持七种语言

默认检查间隔为 1 秒，可按 0.5 秒的步长调整为 0.5–10 秒。间隔越短，越容易发现短暂连接，但检查次数更多；间隔越长，资源占用较少，但可能错过短暂连接。

程序只对规则匹配的连接记录或提醒，不会把规则以外的普通连接自动判断为可疑。当前版本专注于 TCP；UDP 需要不同的底层追踪方式和更复杂的应用归属判断，因此暂不包含在本版本中。

## 核心设计

- **规则优先**：只有符合已启用规则的连接才会被处理。
- **一次记录**：持续存在的同一连接不会每秒重复写入。
- **真实时间结束判断**：连接从 Windows 列表中消失满 2 秒后才标记为结束；2 秒内重新出现仍属于同一条观察记录。
- **应用信息是调查线索**：程序会尽可能收集进程、PID、文件信息、父级或宿主进程和相关 Windows 服务，但这些信息不能绝对证明最终是谁发起了连接。
- **界面与数据分开**：“清空显示”只隐藏事件页面中的旧记录，不删除 CSV 日志。
- **本地运行**：程序不读取数据包正文，不上传规则或日志。只有用户手动检查更新或打开反馈页面时，才会访问 GitHub。

## 项目结构

```text
connection-watcher/
├── ConnectionWatcher.sln
├── RELEASE_NOTES.md
├── src/
│   ├── ConnectionWatcher.Core/       # 规则、监控、连接状态、日志和配置
│   └── ConnectionWatcher.App/        # WinForms 界面、语言、托盘和启动体验
├── tests/
│   ├── ConnectionWatcher.Tests/      # 核心功能和兼容性测试
│   └── ConnectionWatcher.UiSmoke/    # 多语言、DPI 和布局测试
├── docs/                             # 各语言项目说明和使用说明
├── learning/                         # 开发者教程和学习材料
├── scripts/build-release.ps1         # 构建、测试、打包和整理发布文件
├── packaging/                        # Inno Setup 安装包定义
└── Final-Share/                      # 给普通用户的最终分享目录
```

主要部分的职责如下：

- `ConnectionWatcher.Core` 不依赖具体窗口，负责规则判断、读取 Windows TCP 表、跟踪连接生命周期、收集进程背景、读写 CSV 和保存设置。
- `ConnectionWatcher.App` 负责用户界面、规则编辑、事件详情、帮助中心、托盘提醒、弹窗警报、语言切换和启动画面。
- `tests` 用来确认核心行为没有被改坏，并检查不同语言和窗口缩放下的布局。
- `scripts` 负责按固定顺序构建、运行测试、发布自包含程序、生成安装包、复制最新文档和生成 SHA-256 校验文件。
- `artifacts` 是程序的原始发布输出，`dist` 是安装器输出，`Final-Share` 是最终给用户的分享内容。它们都可以重新生成，不是源代码的替代品。

安装包对用户仍然是一个文件：`SocketSight-Setup-win-x64.exe`。安装后的程序采用自包含的多文件发布方式，所需运行文件会一起安装到程序目录。

## 构建与验证

在 Windows 上构建源代码需要 .NET 8 SDK 和 Inno Setup。

```powershell
dotnet build ConnectionWatcher.sln --configuration Release
dotnet run --project tests\ConnectionWatcher.Tests\ConnectionWatcher.Tests.csproj --configuration Release
```

维护者可以运行：

```powershell
scripts\build-release.ps1
```

该脚本会依次完成构建、功能测试、界面测试、发布、安装包生成、文档整理和 SHA-256 校验文件生成。接收者可以用 PowerShell 的 `Get-FileHash` 检查安装包是否完整。
